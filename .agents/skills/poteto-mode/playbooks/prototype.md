# Prototype

The prototype is a throwaway instrument for a decision. Speed beats polish; the rigor is in picking the right design.

1. Name the decision the prototype exists to make. No decision means no prototype; switch to Feature.
2. Build in a scratch directory outside production source, with the lightest stack that shows the idea. For a behavior or timing question, write the smallest script that exercises it.
3. When comparing options, build two or three materially different variants behind one switch (`principle-exhaust-the-design-space`).
4. Observe the thing you are deciding: screenshot each variant and drive the interaction, or log the timing or output.
5. Present the variants, tradeoffs, and a recommendation. Leave product or taste calls no experiment can settle to the user.

**Reply:** the decision, the evidence behind it, and where the throwaway code lives.
