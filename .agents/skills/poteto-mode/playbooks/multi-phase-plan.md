# Multi-phase plan

The plan is the deliverable. Do not implement.

1. If the change is one or two files with an obvious approach, say a plan is unnecessary and stop.
2. Settle open questions with a prototype (`prototype.md`) before writing. Ask the user only about product or preference calls.
3. Write the plan: what changes, the phases or pull requests in landing order, which depend on which, and the files each touches. Each phase is one change with its own evidence (`principle-sequence-verifiable-units`): what it depends on, what it builds, the result you can see, and how it is verified on the real surface.
4. Hand back the plan. Execution starts when the user says go.

**Reply:** the plan location, the phases with their dependencies, and what remains unproven.
